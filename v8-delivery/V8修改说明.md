## forward 数据流与尺寸

Backbone → PixelDecoder → mask_features [B,D,Hm,Wm] 与三层 multi_scale_features。
Decoder 内：mask_features → Encoder → 三张 [B,1,Hm,Wm] logits。
sigmoid 后拼接 [B,3,Hm,Wm] → Conv3x3 → 与 mask_features 残差融合，得到 [B,D,Hm,Wm]。
Center logits → sigmoid → 有效区域局部极大值 → Top-K → 几何特征采样 [B,K,D]。
Linear(D,C) → 置信度加权残差 → 前 K 个 learnable Query。
保留其他 Query，总初始化尺寸仍为 [Q,B,C]。
Cross-Attention/Self-Attention/FFN 的顺序不变。
Mask Head 继续执行 query mask embedding × mask feature。
pred_logits [B,Q,num_classes+1]、pred_masks [B,Q,Hm,Wm]、aux 层数保持不变。
仅训练期间添加内部 tree_geometry/query_features 字段；推理结果格式保持原样。

MASK_FEATURE_FUSION=True 时，几何特征用于原 Mask Head；False 时只用于 Query 初始化。
投影层零初始化，使 Query 残差初始为零；融合卷积小幅初始化。
融合卷积非零，因此完整 V8 初始化不保证与 baseline 数值完全一致。

## 几何目标与损失的明确约定

- Center：每个实例单独计算内部 EDT，取最大点，在 feature 分辨率生成高斯热图；实例间取最大值。
- Boundary：每实例独立进行 3x3 dilation/erosion，合并边界；缩小时用 max pooling 保留细边界。
- Distance：每实例内部 EDT 除以该实例最大值，合并时取最大值。
- Distance 是“到边界的内部距离”，不是“到中心的径向距离”。两种定义不能混写。
- Padding：所有新增 dense loss 和中心采样排除接触 padding 的 feature cell。
- Center loss：heatmap focal，正样本为热图值 1 的中心。
- Boundary loss：带正类平衡的 BCE + Dice。
- Distance loss：前景 Smooth L1 + 0.1 倍背景 Smooth L1。
- Mask Boundary Dice：匹配后的最终实例 mask 上计算，与 dense Boundary 分支 loss 是两种不同损失。
- 几何、separation 和 Mask Boundary loss 不复制为 aux loss；aux 仍计算原分类/BCE/Dice。
- 所有新权重必须在 weight_dict 注册，本补丁已经完成注册。

GT 基于增强后的 masks 生成，与训练输入对齐。EDT 在 CPU 上通过 scipy 计算，SciPy 已在原 requirements。
这是一份完整功能实现建议；CPU EDT 每次 forward 的开销尚未测量。后续可移到数据 mapper 或采用已验证的缓存路径。
不要缓存增强前的坐标图，否则随机裁剪/缩放后会错位。

## Hungarian 几何代价

C = class_weight*C_class + mask_weight*C_mask + dice_weight*C_dice + geometry_weight*C_geometry。
C_geometry 是预测概率 mask 的软质心与 GT mask 质心之间的归一化 L1 距离。
预测质心与 GT 质心使用同一 padded image 坐标系；预测质心计算排除 padding。
这里使用的是质心一致性，不是将所有 Query 强行绑定到 Top-K 中心。
EDT 最大点只用于 Center heatmap；不能混用 EDT 最大点和质心作为同一定义。
匹配本身在 no_grad 中，不会通过 SciPy 分配反向传播。
GEOMETRY_MATCH_COST=0 可以独立关闭；建议以 V8-B 为起点评估再加入该项。

## Query separation 的正负样本

Hungarian 在每层是 1:1，同一层没有“同 GT 多个 matched Query”的正样本。
正样本：相邻 Decoder 状态中分别匹配到同一 GT 的 Query；按 GT index 对齐，不能按 Query slot 对齐。
正项：1 - cosine(q_left, q_right)，两侧均保留梯度。
负样本：最终层中匹配到不同 GT、且 GT 质心距离不超过 SEPARATION_RADIUS 的 Query。
负项：relu(cosine(q_i,q_j) - SEPARATION_MARGIN)。仅计算上三角，排除自配对。
没有正/负样本时，对应项返回可反传零值。
loss_query_separation 是两项加权之和，再乘 SEPARATION_WEIGHT。
若没有辅助 Decoder 状态，正项自然为零；一个或零个实例时负项为零。
这只是可实现的研究设计，不能未经实验声称降低粘连、提高 AP 或达到某种期刊标准。

## 配置与消融

现有 config 不填写 TREE_AWARE 时，add_maskformer2_config 提供默认：ENABLED=False，V6B/V7 保留。
完整 V8 yaml 设置 LEGACY_EDGE_REFINE=False、LEGACY_QUERY_ADAPTER=False，模型中不构建这两个旧模块。
baseline.yaml 同时关闭 TreeAware 和 Mask Boundary loss，恢复本分支中这些局部路径的原始逻辑。
这不构成“整个仓库与某个官方 release 完全一致”的证明，严格论文 baseline 仍需逐提交核对。

- baseline.yaml：原始 Query 路径；无 V6B/V7；无新增损失。
- v8_a.yaml：Center loss + Hybrid Query；Boundary/Distance 分支仍通过几何融合隐式训练，但无独立监督。
- v8_b.yaml：三分支完整监督与 Mask Feature 融合；无 geometry match/separation。
- tree_aware_v8.yaml：完整 V8-C，额外启用 geometry match 与 separation。

所有示例继承仓库中真实存在的 COCO R50 配置，以避免编造单木数据集注册名。
用于单木实验时，将 tree_aware_v8.yaml 的 _BASE_ 改为你已有的单木配置，并确认 NUM_CLASSES、DATASETS、Q、batch size 等。
不要直接用 COCO 的 80 类设置解释为单木实验；本交付没有假设你的数据集路径或注册方式。
NUM_GUIDED_QUERIES=-1 自动采用 Q 的一半；明确值必须在 [1,Q]。Q=700 的自动 K 为 350。
参数数值是建议起点，不是经过调参或验证的最优值。
