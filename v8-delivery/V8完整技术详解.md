## 1. 原任务与本次修改的边界

任务是遥感影像中的单木实例分割：同一类别的每棵树都要得到独立 mask。分类正确但两棵树合成一个 mask，仍然是实例分割错误。

新增设计针对三个可能的困难：定位候选实例、表示树冠形状、区分相邻实例。它们分别对应 Center、Boundary/Distance、Query separation。

这些是研究动机，不意味着每种困难都只能靠这些模块解决，也不意味着增加模块必然提高 AP。

本补丁遵循以下工程约束：保留训练入口、原有配置键、原始类别/mask 输出尺寸、原 Decoder 更新顺序和原点采样损失。新增配置是向后兼容扩展；训练内部字典增加字段，因此不能称为“所有内部接口完全不变”。

没有更改数据集注册、训练调度、学习率、优化器、数据增强、Backbone 或 CUDA 算子实现。

## 2. 原始 Mask2Former 实际在做什么

### 2.1 Pixel Decoder 的三项输出

`MaskFormerHead.layers()` 调用 `pixel_decoder.forward_features(features)`，取得：

```python
mask_features, transformer_encoder_features, multi_scale_features
```

`mask_features` 为 `[B,D,Hm,Wm]`，用于生成 mask。多尺度特征是长度为 3 的列表，用于 Transformer Cross-Attention。`D` 来自 `MASK_DIM`，不是必须写死为 256。

一般配置下 `Hm≈Hpad/4`、`Wm≈Wpad/4`；补丁通过实际 tensor shape 取尺寸，没有把缩放比例硬编码为 4。

### 2.2 两个 Query embedding 的区别

原 Decoder 有两个 embedding：

```python
self.query_feat = nn.Embedding(Q, C)
self.query_embed = nn.Embedding(Q, C)
```

`query_feat` 是 Query 内容的初始状态；`query_embed` 是 Query 槽的可学习位置编码。两者形状相同，但作用不同。

进入 Decoder 时，对 batch 复制得到 `[Q,B,C]`。`Q` 是候选实例槽数，不是当前图像的真实树木数量。

所有图像原本共享同一组 Query 初始内容。不同图像的信息在后续 Cross-Attention 中进入 Query。V8 改的是这个内容初始化，让部分 Query 在进入 Decoder 之前已包含当前图像的局部信息。

### 2.3 原 Decoder 更新顺序

实际源码每层的顺序是：

```text
Masked Cross-Attention → Self-Attention → FFN → Prediction Heads
```

不是根据图中模块摆放位置推测的 Self-Attention 优先。本补丁保留上述顺序。

Cross-Attention 读取一个尺度，层编号通过 `i % 3` 轮换尺度。之前预测的 mask 生成布尔 attention mask；完全屏蔽的行会被取消屏蔽，避免没有可注意位置。

### 2.4 Query 如何生成 mask

经 LayerNorm 后的 Query 用于分类 Linear 和 mask embedding MLP。Mask MLP 输出 `D` 维向量，与每个像素的 `D` 维特征做内积：

$$M_{bqhw}=\sum_{d=1}^{D} E_{bqd}F_{bdhw}.$$

实现是：

```python
torch.einsum('bqc,bchw->bqhw', mask_embed, mask_features)
```

因此改变 Query 内容或 mask feature 都能改变 mask，但两条路径机制不同。V8 配置可分别研究 Query 增强和 Mask Feature 融合。

## 3. 原仓库已有 V3/V6B/V7，不是纯官方 baseline

本次补丁的基准中已有：

- 最终层的实例 Boundary Dice。
- Pixel Decoder 的 V6B 高频残差增强 `mask_refine`。
- 每层 FFN 后的 V7 `center_adapter`。

如果不处理旧模块，就会变成 V7 上叠加新模块，无法把变化明确归因于 V8。

我没有直接删除旧实现，而是增加 `LEGACY_EDGE_REFINE`、`LEGACY_QUERY_ADAPTER` 开关。旧配置默认开启，避免旧实验行为被突然改变；V8 和新的 baseline 配置关闭。

关闭时不构建对应模块，既减少参数，也避免“参数存在、forward 不使用”引发的 DDP unused parameter 问题。

`baseline.yaml` 关闭了本分支中这些可识别的新增路径。但它不证明整个仓库和某个官方 release 完全一致：其他历史修改、依赖版本、数据集流程和训练参数仍需要核对。

## 5. 完整 forward 数据流

```text
image → normalization → ImageList padding → Backbone
                                          ↓
                                    Pixel Decoder
                                          ↓
                        mask_features F [B,D,Hm,Wm]
                             ├── Center branch → Zc
                             ├── Boundary branch → Zb
                             └── Distance branch → Zd
                                          ↓
                     concat(sigmoid(Zc), sigmoid(Zb), sigmoid(Zd))
                                          ↓
                         Fg = F + Conv3x3(priors)
                             ├── Center peaks + sample Fg
                             │                ↓
                             │          Query residual
                             │                ↓
                             │    hybrid queries [Q,B,C]
                             │                ↓
                             │         original Decoder
                             │                ↓
                             │      class/mask embeddings
                             │                ↓
                             └────────── Mask Head
                          Fg or F, chosen by config
```

Cross-Attention 的输入仍是原三层多尺度特征，未替换为三张几何图。

推理时预测几何图也会生成，因为 Query 和可选 Mask Head 需要它们。只有 GT 构建和新增监督不在推理期间执行。

## 6. `TreeGeometryEncoder`：逐层解释

### 6.1 分支宽度

```python
width = max(8, mask_dim // 4)
```

输入 `D=256` 时中间宽度为 64。这是降低分支参数量的瓶颈设计。最小宽度 8 避免小维度配置把分支压得过窄。这个比例是经验起点，不是理论最优。

### 6.2 每个分支的结构

```python
Conv2d(D, width, 3, padding=1)
GroupNorm(1, width)
ReLU()
Conv2d(width, 1, 1)
```

3×3 卷积读取局部邻域，保持 Hm/Wm；GroupNorm 不依赖 batch 内样本数，适合高分辨率、小 batch 的训练；ReLU 增加非线性；1×1 卷积把局部特征压成一张响应图。

`GroupNorm(1,width)` 在每个样本内对全部通道与空间位置归一化。它不是逐像素通道归一化，也不是 BatchNorm。padding 区域仍参与这一归一化统计，这是当前实现的限制之一。

三个分支各自实例化，参数不共享。共享输入，不代表共享卷积权重。

### 6.3 Logits 与概率

三个分支输出没有立刻作为返回值 sigmoid，保留原 logits：

```python
center_logits, boundary_logits, distance_logits
```

损失函数可从 logits 以更稳定的方式计算 BCE；几何融合与 Query 评分时再 sigmoid 到 `[0,1]`。

Distance 的 sigmoid 是有界回归输出，不应解释为“某个距离类别的概率”。

### 6.4 融合

$$P=\operatorname{Concat}(\sigma(Z_c),\sigma(Z_b),\sigma(Z_d))\in\mathbb R^{B\times3\times H_m\times W_m},$$

$$F_g=F+\operatorname{Conv}_{3\times3}(P).$$

拼接后由卷积学习各先验的组合，而不是把 center/boundary/distance 三个语义不同的量直接相加。输出通道仍为 D。

残差保留原 `F`，几何分支只负责增量。几何响应不准确时，原语义特征仍存在，但这不保证预测一定不退化，因为残差和后续权重仍可改变结果。

### 6.5 初始化

- 融合卷积权重为正态分布，标准差 `1e-3`；bias 为零。
- Center 最后一层 bias 为 `-2.19`。
- 其他分支遵循 PyTorch 默认初始化。

`sigmoid(-2.19)≈0.101`。当卷积贡献接近零时，初始中心置信度约为 0.1，降低初始大面积高置信预测。随机卷积响应也参与 logits，不能声称每个像素初始概率都严格等于 0.1。

融合卷积小幅但非零，所以 `Fg` 初始通常不等于 `F`。当 `MASK_FEATURE_FUSION=True` 时，完整 V8 初始输出不能宣称和 baseline 数值完全一致。

## 7. `TreeAwareQueryGenerator`：每个操作的理由

### 7.1 Query 数量

自动 `K=max(1,Q//2)`。明确设置 K 时要求 `1≤K≤Q`。这样支持 Q=1，也不会超出原 Query 数。

实际采样数为 `k=min(K,Hm×Wm)`，避免 feature 很小却调用过大的 Top-K。

通常 Q=700、K=350：前 350 个 Query 可增强，后 350 个保持原内容初始化。Q=100 时自动 K=50。Q 未改变，不是“额外加 350 个 Query”。

### 7.2 有效区域

Center 概率转 float32，padding 位置的 NMS 输入设为 -1。概率本来非负，因此有效峰值优先。

局部极大值与 padding 检查同时成立的点才是候选。没有 padding mask 的直接调用会把全部 feature cell 当有效区域。

### 7.3 局部峰值

```python
pooled = max_pool2d(scores_for_nms, kernel, stride=1, padding=kernel//2)
peaks = (scores_for_nms == pooled) & valid
```

每个点与邻域最大响应比较。这样避免直接对所有像素 Top-K 时围绕一个中心连续挑选相邻像素。

这是局部最大值筛选，不是严格的逐候选贪心 NMS。相等的平台响应会保留多个相邻位置；Top-K 遇到同分值时的顺序不能当成稳定的空间身份。

`kernel=5` 表示 feature 上 5×5 邻域。通常 stride 4 时它涉及约 20×20 输入像素尺度，但具体 receptive field 还包含前级网络，不能只按这 20×20 解释模型感受野。

### 7.4 Top-K 与不足候选

非峰值被设为 -1 后排序。如果有效峰值少于 k，Top-K 会选到补齐的非峰值索引。

实现再乘 `peaks.gather(...)`，使这些补齐项的 confidence=0，因此 Query 残差=0。它们不会被当成真实中心，但算子仍会 gather 相应特征。

本版没有固定 confidence 阈值。只要是有效局部峰值，即便置信很低也可能入选，但残差被低 confidence 缩小。

### 7.5 特征采样

`Fg.flatten(2).transpose(1,2)` 把 `[B,D,Hm,Wm]` 变成 `[B,HmWm,D]`。

展平索引对应行优先的二维位置。`gather` 在这些整数像素位置读取特征，得到 `[B,k,D]`。这不是 bilinear grid_sample，也没有亚像素坐标回归。

### 7.6 投影与融合公式

投影 `Linear(D,C,bias=False)` 允许 MASK_DIM 和 HIDDEN_DIM 不相等。没有 bias，零特征不会仅凭一个固定 bias 产生与图像无关的几何增量。

对第 i 个选中点：

$$\Delta q_i=0.1\,s_i\,W_p f_i.$$

$$q_i^{(0)}=\begin{cases}q_i^{learn}+\Delta q_i,&i<k\\q_i^{learn},&i\ge k.\end{cases}$$

`0.1` 是硬编码的残差缩放，不是 config 开关或学习参数。它减少初期扰动，尚未证明是最佳比例。

最终把残差转回原 Query dtype，再返回 `[Q,B,C]`。只改变 Query 内容，原 `query_embed` 完全保留；选中中心坐标没有单独注入位置编码。

### 7.7 零初始化与第一步梯度

`W_p` 初始为零，所有 Query 残差初始为零。第一步中投影权重通常仍能获得梯度，但经 `Wp` 传到采样特征/置信度的这条梯度路径初始为零。

Center/Boundary/Distance 仍由各自直接监督训练；开启 Mask Feature Fusion 时还有 mask 路径的梯度。投影更新后，Query 路径才逐渐影响前级几何特征。

### 7.8 Top-K 的可导边界

`topk(...).indices` 和峰值布尔比较不可导。Loss 可以更新选中位置的 features、confidence、projection，但不能直接对“索引坐标移动”求梯度。

所以 Center loss 是定位学习的重要来源。不要把这个实现称为完全可微的中心定位器或声称 Mask loss 自动覆盖所有漏选中心。

## 8. Padding 为什么必须单独处理

不同图像组成 batch 时，`ImageList` 把它们补到统一尺寸。真实图像以外的像素是 padding，不应被当作真实背景训练中心预测。

`MaskFormer.forward()` 按 `images.image_sizes` 建立 `[B,Hpad,Wpad]` 的布尔 mask：True 为 padding，False 为图像内容。

`resize_padding_mask` 用 adaptive max pooling 下采样。下采样窗口里只要含 padding，就将对应 feature cell 标为 padding。这是一种保守方案，避免边界混合 cell 带来虚假中心。

代价是靠近非整除边界的少量真实内容也可能被排除。adaptive pooling 的窗口定义也不等于精确的 Backbone receptive field；这里的 mask 是监督/候选筛选近似，不是感受野级严格有效性证明。

本补丁只保证新增几何 loss、Query 峰值筛选、几何质心成本及新增 Mask Boundary loss 使用有效区。原 Cross-Attention 仍 `memory_key_padding_mask=None`，原 point mask loss 的 padding TODO 也没改。

因此不能说“全网络所有 padding 影响都消除了”。卷积和 GroupNorm 的统计仍可能受到 padded 输入影响。

## 9. `build_tree_targets`：逐实例目标生成

### 9.1 生成时机

数据 mapper 已完成裁剪、翻转、缩放等增强后，`prepare_targets()` 取得变换后的 GT masks，再 padding 到 batch 尺寸。输出几何图的尺寸来自当前预测 `center_logits.shape[-2:]`。

这样监督图与实际输入坐标一致。若缓存未经增强的监督图，又不做同样的变换，会产生位置错位。

`@torch.no_grad()` 表示目标生成不进入模型的反向图。它不表示 GPU 不需要执行任何 resize 操作，也不表示没有 CPU/GPU 同步。

### 9.2 EDT 定义

对每个实例二值 mask Mi：

$$d_i(p)=\min_{r:M_i(r)=0}\|p-r\|_2,\quad p\in M_i.$$

背景距离为 0，越深入树冠内部距离通常越大。代码对每个 mask 额外补一圈零再求 EDT，定义图像边缘和全前景实例的外部背景。

这个先验适合一定程度上具有紧致内部的树冠，但不意味着真实树干位置一定等于 EDT 最大点。遮挡、裁剪、不规则或多峰树冠都会破坏这一近似。

### 9.3 为什么不是 union 的 EDT

先把相邻两棵树合并为一个 union 再 EDT，会把内部实例边界丢掉，可能只留下一个大中心。逐实例计算保留独立身份，然后才合并 dense 目标。

### 9.4 Center 目标

对 EDT 做 argmax，选中最大距离像素。若最大值有平台，NumPy argmax 选择展平顺序中的第一个最大值，不是平台中心；这是确定性的简化，可能引入位置偏移。

原分辨率像素中心 `(x+0.5,y+0.5)` 按实际宽高缩放：

$$x_m=\left\lfloor(x+0.5)W_m/W_{pad}\right\rfloor,\quad y_m=\left\lfloor(y+0.5)H_m/H_{pad}\right\rfloor.$$

floor 后 clip 到有效索引范围。然后在 feature grid 上生成：

$$Y_c(u,v)=\exp\left[-\frac{(u-x_m)^2+(v-y_m)^2}{2\sigma^2}\right].$$

中心格子的值严格为 1，便于 heatmap focal 判断正样本。多个实例取逐像素 max，避免相加超过 1。

固定 `sigma=2` 使用 feature 像素单位。它不随树冠大小变化；两棵小树中心落在同一格会合并，靠得很近时高斯与 NMS 也可能降低可分性。

### 9.5 Boundary 目标

每个 mask 用 3×3 全 1 structuring element 做 dilation 和 erosion：

$$B_i=\operatorname{dilate}(M_i)\land\neg\operatorname{erode}(M_i).$$

它包含轮廓内侧和外侧的带状像素，不是只有内部一像素线。erosion 指定图像外 `border_value=0`，裁剪边缘具有明确的背景约定。

逐实例边界取 max 合并，保留相邻实例的分界。下采样用 max pooling，尽量避免细边界消失，但也可能让 feature 上边界变粗、邻近边界连成带。

它是二值形态学边界，不是遥感图像梯度或网络高频残差，两者不能混为一种监督。

### 9.6 Distance 目标

$$\widetilde d_i=d_i/\max(d_i).$$

逐实例归一化后，大树和小树的中心都接近 1，减少绝对树冠尺寸对值域的影响。也因此不再保留“距离是多少米/像素”的绝对尺度。

每实例距离图 bilinear resize 到 `[Hm,Wm]`，再取 max 合并。`align_corners=False` 与常见像素中心 resize 约定一致。下采样后最大值不一定仍严格等于 1，因为没有再次归一化。

Distance 是到边界的内部 EDT，不是到中心的径向距离。你原图/文字中的两种定义不同，本补丁明确采用前者。

### 9.7 Foreground、有效区和空实例

Foreground 由每实例二值 mask 的 max pooling 结果合并，用于分开 Distance 的前景/背景平均误差。

无前景的单实例 mask 会跳过几何生成，防止 EDT 最大值为 0 时除零；其原 label/mask 未从原训练目标中删除，所以不意味着补丁清洗了无效标注。

没有任何实例时，center/boundary/distance/foreground 都为零，valid 仍由图像尺寸定义。所有图最后乘 valid。

## 10. 两种“中心”的严格区别

Center heatmap 使用 EDT 最大点；geometry matching 和 separation 邻近筛选使用 mask 质心。

质心对于概率 mask P 定义为：

$$c_x=\frac{\sum_{x,y}P(x,y)(x+0.5)/W}{\max(\sum P,10^{-6})},\quad c_y=\frac{\sum_{x,y}P(x,y)(y+0.5)/H}{\max(\sum P,10^{-6})}.$$

先乘 valid，再转 float32。输出为归一化 `(x,y)`，注意不是 `(y,x)`。

EDT 最大点倾向于最厚实的内部；质心描述质量平衡。它们在不规则树冠上通常不同，质心甚至可能位于凹形 mask 外。

匹配两端都用质心，是为了比较同一定义。不能把 predicted soft centroid 和 GT EDT peak 混在一起，然后称为质心误差。

空 mask 的分母 clamp 防止 NaN；全零输入输出 `(0,0)`，并没有一个有意义的中心。GT 空 mask 应优先由数据检查处理。

## 11. `TreeAwareSetCriterion` 的组织设计

新增类继承已有 `SetCriterion`，复用分类 CE、PointRend 点采样、Mask BCE/Dice、permutation helper 与 repr 等已有逻辑。

没有直接把全部 V8 插进旧 criterion，目的是让 `ENABLED=False` 时仍选用原 criterion，便于旧实验复现。

但 override 了 `forward` 来明确组织最终匹配、最终损失、几何监督、aux 匹配和 separation。这样同一轮匹配结果直接用于对应损失，不需要重复随机匹配来找 Query 正负对。

完整顺序：

```text
final Hungarian assignment
→ distributed num_masks
→ 原分类 / point mask losses
→ 可选 final Mask Boundary Dice
→ Center / Boundary / Distance dense losses
→ 每个 aux state 独立匹配及原损失
→ 使用已保存的各 state assignment 计算 Query separation
```

`targets=None`、batch=0 等非标准训练输入没有支持；正常实例分割训练必须提供合法 GT。分类为空实例时仍训练 no-object。

## 12. 原有损失和空匹配处理

### 12.1 原分类 CE

匹配到 GT 的 Query 取对应类别；未匹配 Query 取 no-object 类。`NO_OBJECT_WEIGHT` 控制 no-object 类权重。单木实例分割仍需要“tree + no-object”两个输出维度，不等于 Q 个树木类别。

### 12.2 原点采样 Mask BCE/Dice

仍复用原 uncertainty/random point sampling：在匹配后的 mask 上采样点，估计 BCE 与 Dice。与新的 dense geometry loss 不同，它不是整张原图的逐像素 BCE。

### 12.3 空匹配分支

当整个 batch 没有任何匹配 mask 时，返回：

```python
zero = outputs['pred_masks'].sum() * 0.0
```

Mask/Dice 为零但保留反向图；不运行可能不支持 0 个实例的 PointRend 采样。该防护在 V8 criterion 内，不保证原 baseline criterion 的所有空 GT 路径都已修复。

## 13. Center Heatmap Focal Loss

代码从 center logits sigmoid 后 clamp 到 `[1e-4,1-1e-4]`，避免 `log(0)`。

对 valid 像素：

$$\ell_c=\begin{cases}-(1-p)^2\log p,&y=1\\-(1-y)^4p^2\log(1-p),&y<1.\end{cases}$$

这个式子是 heatmap focal：高斯邻域 y 在 0 和 1 之间时，不把它当成 soft-label BCE，而是降低附近负样本惩罚。

`p²` 降低已经正确预测为背景的点的贡献；`(1-p)²` 聚焦较难的中心正样本；`(1-y)^4` 允许真实中心周围存在一定响应。

每张图有中心时除以中心正样本数；没有有效中心时除以有效像素数；最后对图像取平均。

空图不会因分母为 0 崩溃。clamp 以外的极端概率梯度会被截断；更严格的数值实现可考虑 logits/logsigmoid 形式，但本补丁没有这样重写。

## 14. Dense Boundary BCE + Dice

正类权重：

$$w_+=\operatorname{clamp}\left(\frac{N_{valid}-N_{positive}}{\max(N_{positive},1)},1,20\right).$$

边界稀疏，普通 BCE 容易被背景主导，因此正类上调；上限 20 避免极端少边界图把梯度放得过大。计数是在本地 batch 全部有效像素上进行，不是每个实例独立计数。

计算无 reduction 的 logits BCE，正像素乘 w+，背景乘 1，乘 valid 后除以 valid 总数。

Dense Dice 对每张图计算：

$$\ell_{dice}=1-\frac{2\sum py+1}{\sum p+\sum y+1}.$$

平滑常数 1 避免空边界分母为零。BCE 提供逐像素约束，Dice 提供整体重叠约束。返回两者相加，再由 `BOUNDARY_WEIGHT` 统一缩放；没有分别调 BCE/Dice 权重的配置。

一个 dense Boundary map 是所有 GT 实例边界的合并图，它本身没有实例 ID。

## 15. Distance 回归损失

预测为 `sigmoid(distance_logits)`。设 e 是 default `smooth_l1_loss` 的逐像素值：

$$L_d=\operatorname{mean}_{foreground}(e)+0.1\operatorname{mean}_{background}(e).$$

两个区域分别归一化，所以大量背景不能只凭像素数占比完全主导梯度。空区域分母 clamp 为 1，对应零贡献。

默认 Smooth L1 的 beta=1；预测与目标都在 `[0,1]`，误差绝大多数处于二次段，近似 `0.5*(p-y)^2`，不要把此处解释为始终处于 L1 段的强鲁棒回归。

背景监督也使用 resize 后的目标值，插值边缘可能是小正值；没有强行把 background 的 Distance target 再清零。背景权重 0.1 硬编码，没有独立 config。

## 16. 匹配后的实例 Mask Boundary Dice

这项 `loss_boundary` 与上节 `loss_tree_boundary` 不同：

| 比较项 | loss_tree_boundary | loss_boundary |
|---|---|---|
| 预测来源 | 单通道几何 Boundary 分支 | 最终 Q 个实例 mask |
| 是否匹配 | 不需要 Hungarian | 只计算 matched masks |
| GT | 合并实例边界图 | 每个匹配 GT mask 的边界 |
| 损失 | BCE + Dice | Boundary Dice |
| 权重 | BOUNDARY_WEIGHT | MASK_BOUNDARY_WEIGHT |

V8 override：预测 sigmoid、GT nearest resize、乘 valid，再调用已有可微 `morphological_boundary`，最后再乘 valid。

概率 mask 的 dilation/erosion 由 max-pooling 构成分段可导近似。它不是先 threshold 预测成硬 mask，否则会阻断梯度。

GT 边界为空的实例不计该项；总和除以原 `num_masks`，没有只按有效边界实例重新归一化。near-border 排除可能削弱部分边界监督。

只对最终预测计算此项。完整 V8 保留了这一来自旧版本的监督思想，但关闭了 V6B/V7 结构。这应在论文对照中明确标注。

## 17. Hungarian geometry matching

### 17.1 原成本没有删除

$$C_{ij}=\lambda_{cls}C^{cls}_{ij}+\lambda_{mask}C^{mask}_{ij}+\lambda_{dice}C^{dice}_{ij}+\lambda_{geo}C^{geo}_{ij}.$$

原分类成本为负预测类别概率，BCE/Dice 成本通过共享随机点计算。新增部分为：

$$C^{geo}_{ij}=\|c_i^{pred}-c_j^{GT}\|_1.$$

预测 soft mask 的质心和 GT 二值 mask 的质心都使用 padded image 坐标归一化。`torch.cdist(...,p=1)` 形成 `[Q,Ngt]` 矩阵。

### 17.2 它改变的是对应关系

matching 在 no_grad 中，经 SciPy `linear_sum_assignment` 得到离散对应关系。这项不是一个另行反传的 `loss_center_match`，也不是直接修改 inference score。

它通过选择“谁负责哪个 GT”间接改变后续监督。没有把 Top-K 第 i 个中心固定绑定到第 i 个 GT。

### 17.3 训练早期的风险

初始 soft masks 可能大面积接近均匀背景，各 Query 的质心都在图中部。此时新增几何成本不一定可靠。

默认 0.2 只是起点。V8-B 关闭该项，可在中心/mask 稳定后单独评估是否加入；本补丁没有自动 warm-up scheduler。

### 17.4 与 aux 的关系

criterion 对每个 aux state 也调用同一个 matcher，所以 `GEOMETRY_MATCH_COST>0` 时几何成本也作用于 aux assignments。

“新增几何 loss 只返回一个 key”不等于“matcher 的几何成本只作用于最终层”。

### 17.5 空 GT 与其他细节

空 GT 时直接返回两个空索引，不再采样点或调用 SciPy。最终索引按原接口返回 CPU int64，使用时按需转到 tensor 所在设备。

原成本仍需至少一个非零；没有仅依靠几何匹配的模式。未检查所有成本参数是否非负，因此不应随意填写负数。

sigmoid 在 soft centroid 前仍按当前 logits dtype 执行，然后在 helper 内转 float32。它改善累加精度，不证明消除了 AMP 下所有 sigmoid 极值问题。

## 18. Query Separation：实现与原图的区别

### 18.1 为什么必须定义正样本

每个预测 state 的 Hungarian 是 1:1。同一 state 同一 GT 只有一个 matched Query，不存在直接的“同 GT 两个 matched Query”正样本。

因此图中的同实例吸引必须补充来源。本补丁选择跨相邻预测状态，按 GT index 找共同实例。

### 18.2 保存哪个 Query 表示

每个预测状态保存：

```python
self.decoder_norm(output).transpose(0, 1)
```

得到 `[B,Q,C]`，即送入 prediction heads 的标准化 Query 内容。没有额外 projection head，也没有保存 mask embedding D 维向量来做 separation。

初始 Query 也有一次预测，所以 states 包括“初始化预测 + 每个 Decoder 层”。正样本对包含初始化与第一层，不只是实际 Decoder 层之间。

### 18.3 正项

不同 state 的 Query slot 不保证身份一致。例如 state A 的 Q2 和 state B 的 Q9 都匹配 GT3，才构成正样本；A 的 Q2 和 B 的 Q2 若匹配不同 GT，则不是正样本。

用 `left_tgt[:,None] == right_tgt[None,:]` 寻找共同 GT，再取对应 Query。每层 target indices 唯一，因此同 GT 形成至多一对。

L2 normalize 后：

$$L_{pos}=\operatorname{mean}(1-\hat q_l^T\hat q_{l+1}).$$

两侧都保留梯度，没有 teacher detach。目标是同实例的表征跨更新状态更一致，但可能约束 Decoder 必要的表征变化，尤其初始状态与第一层差异较大时，需要消融正项权重。

### 18.4 负项

仅在最终 state 中，对 matched 不同 GT 的 Query 构造候选。GT 质心的欧氏距离不超过 radius 才算邻近：

$$\mathcal N=\{(i,j):i<j,\|c_i-c_j\|_2\le r\}.$$

$$L_{neg}=\operatorname{mean}_{\mathcal N}\max(0,\hat q_i^T\hat q_j-m).$$

上三角排除自配对与重复计数。m=0.2 表示相似度超过 0.2 才罚，不是“欧氏距离至少 0.2”。

邻近优先是为了集中在潜在粘连实例，避免强迫所有远处同类别树木互相远离。但代码没有检查树冠是否实际接触，质心距离只是一种粗代理。

归一化坐标半径 0.15 受 padded size 和长宽比影响，不是固定米数；不同 batch padding 也会改变邻近集合。

### 18.5 合并与空对

$$L_{sep}=w_{pos}L_{pos}+w_{neg}L_{neg}.$$

再乘 `SEPARATION_WEIGHT`。无 pairs 时以可反传零值返回，分母至少 1。

负对只使用 matched Queries。未匹配 Query 重复预测同一棵树，仍主要依靠原 no-object 分类监督；不能声称这项直接排除了所有重复实例预测。

### 18.6 final-only 的准确含义

separation 返回一个无 `_0/_1` 后缀的 key，但正项读取多个 aux states。它不是仅对 final tensor 做运算。

若没有 aux states，正项为零。关闭 `DEEP_SUPERVISION` 并不自动删除 Decoder 输出的 aux states；原模型仍生成它们，只是没有 aux loss 权重。因此正项也不会仅因关闭 deep supervision 自动消失。

## 19. 每个原模型文件的具体改动

### 19.1 `msdeformattn.py`

构造函数新增默认 True 的 `legacy_edge_refine`；from_config 读取开关；仅开关为 True 才构建原 `mask_refine`。

forward 中保留原公式：`edge=F-avg_pool(F)`；`refined=mask_refine(concat(F,edge))`；`F=F+0.1*refined`。

我将原展开较长的写法整理成几行，但计算含义未改变。开关 False 时直接对 `out[-1]` 做原 mask feature 投影。三项返回、FPN 和 MSDeformAttn 都未修改。

### 19.2 `mask2former_transformer_decoder.py`

新增默认参数，from_config 传入 V8 设置；V8 关闭时不构建 Encoder/Generator。V7 Adapter 同样只在开启时构建和调用。

保留 `mask` 参数为 `padding_mask`，不再 `del mask`。仅供新 Query peak selection；没有改变原 attention 的 padding 屏蔽方式。

在 `query_feat` batch expansion 后立即生成几何特征、增强 Query。这在首次 prediction heads 之前，所以初始化预测也使用新的 Query。

可选替换局部变量 `mask_features=geometry_features`，不改变外部 Pixel Decoder 接口。

仅 training+tree_enabled 时保存 query_states 和额外输出；inference 字典仍只有原三个字段。预测辅助层数量不变。

### 19.3 `matcher.py`

新增默认 0 的 cost_geometry，并记录到 repr；空 GT 直接跳过；原三种成本后增加质心 L1 成本。

新 helper 来自 tree_geometry，模块 import 会引入 SciPy ndimage，SciPy 本来已是项目依赖。没有添加 requirements 或调整包版本。

### 19.4 `maskformer_model.py`

从 sem_seg_head.predictor 读取实际 tree_enabled 状态；访问采用嵌套 getattr，避免没有 predictor 属性时直接属性异常。

from_config 验证开启 V8 时 predictor 支持 V8，再选择 TreeAwareSetCriterion。硬 Top-K 模式要求 Center weight>0。

先注册原 aux 权重，再注册新权重，防止自动生成无实现的 `loss_tree_center_0` 等 key。

forward 按 ImageList.image_sizes 建 padding mask，借用已有 Head mask 参数转发。GT 是在输出 shape 可用后构建，所以 prepare_targets 新增可选 geometry_size。

prepare_targets 支持 BitMasks.tensor，也继续接受 tensor masks；没有新增 PolygonMasks rasterization。每张图保存 padded masks、几何 GT、padding mask 和质心。

模型原有“按 weight_dict 乘权重，否则丢弃 loss”的逻辑保留。新增损失不注册权重就会被丢弃，因此权重连接不可省略。

## 20. `TreeAwareSetCriterion.forward` 的归一化细节

原 instance mask loss 用 `num_masks`。它先 all_reduce 本地 GT 数，再除 world_size，最后 clamp≥1。结合 DDP 的平均梯度，可实现按跨 rank 实例数归一化的原策略。

Geometry loss 使用本地 batch 的像素/图像平均，separation 使用本地 pair 平均，没有额外 all_reduce denominator。

这些平均分别表达不同目标。不同 rank 有效像素或 pairs 差异大时，DDP 的本地平均再平均不等于全局像素/全局 pair 的严格加权平均。补丁未宣称这些新项具有全局 pair-weighted 归一化。

aux predictions 分别重新匹配，不假设同一 slot 从头到尾对应同一 GT。Geometry predictions 只由同一 Encoder 计算一次，不为每层复制三个几何分支。

所有 scalar loss 最终在 `MaskFormer.forward()` 乘对应外层权重；负/正 separation 内部权重与外层 separation weight 是两级不同缩放。

## 22. 四个 yaml 的真实含义

| 设置 | baseline | V8-A | V8-B | 完整 V8-C |
|---|---|---|---|---|
| V6B / V7 | 关闭 | 关闭 | 关闭 | 关闭 |
| 三分支模块 | 不构建 | 构建 | 构建 | 构建 |
| Hybrid Query | 关闭 | 开启 | 开启 | 开启 |
| Center 监督 | 关闭 | 开启 | 开启 | 开启 |
| Boundary/Distance 监督 | 关闭 | 关闭 | 开启 | 开启 |
| 几何 Mask Feature | 关闭 | 关闭 | 开启 | 开启 |
| Mask Boundary Dice | 关闭 | 关闭 | 开启 | 开启 |
| 几何匹配 | 关闭 | 关闭 | 关闭 | 开启 |
| Query separation | 关闭 | 关闭 | 关闭 | 开启 |

V8-A 并不是“网络里只有 Center 分支”：Boundary/Distance 分支仍存在，并可通过几何融合和 Query 路径间接学习，只是没有各自的监督。若要严格的 center-only 结构消融，需要另加分支构建开关；此补丁没有实现该开关。

V8-A→B 同时改变了 dense supervision、Mask Feature Fusion 和 Mask Boundary Dice；B→C 同时改变了 matcher 与 separation。它们适合阶段开发，但不能单凭这四次实验把每个模块的收益单独归因。

示例 `_BASE_` 指向仓库实际存在的 COCO R50 yaml，没有假定你的单木 dataset 名称。实际单木配置要更换父配置，并检查类别数、数据集、Q、batch size、预训练权重和推理 Top-K。

Q 不变也意味着真实实例数远大于 Q 时，匹配容量仍受 Q 限制；K 不等于最大可检出树数。Q 未匹配的 learnable Query 仍可检出中心分支漏掉的实例。

| query_features | [B,Q,C] | training 新增 |
| tree_geometry | 三张 logits 的 dict | training 新增 |

Prediction head 的维度、分类数量、Q 和原 inference postprocess 没变。不等于 checkpoint 的参数键完全兼容：新增模块必然新增 state_dict keys。

关闭 V6B/V7 后，旧 V7 checkpoint 会有对应 unexpected keys；新几何模块则会缺 missing keys。必须按模块名核对，不能把任何加载错误都吞掉。

开启/关闭结构模块时应重新构建模型。没有为中途动态切换开关或原 optimizer state 完整恢复设计迁移机制。

## 24. 梯度路径汇总

```text
Center loss → center branch → mask_features → PixelDecoder/Backbone
Boundary loss → boundary branch → mask_features → PixelDecoder/Backbone
Distance loss → distance branch → mask_features → PixelDecoder/Backbone

Mask/class losses → Decoder → initialized hybrid queries
                                 ↓
                  projection、sampled features、selected confidence
                                 ↓
                   fusion、geometry branches、mask_features

若 MASK_FEATURE_FUSION=True：
Mask losses → mask feature Fg → fusion + priors + original features

Separation → matched query states → Decoder / hybrid query path
```

没有梯度穿过 NumPy/SciPy GT 构建、Hungarian assignments、peak boolean mask 和 Top-K indices。

额外 loss 会影响 Backbone，因此虽然没有改 Backbone 源码，它的训练梯度仍会改变。不要把“没改文件”理解为“训练行为完全不受影响”。

## 25. 参数量与计算量：不能只说模块很轻

假定 `D=C=256`、branch width=64，按当前 bias/GN 结构计算：

| 项目 | 参数量 |
|---|---:|
| 单分支 Conv3x3 + GN + Conv1x1 | 147,713 |
| 三个分支合计 | 443,139 |
| fusion Conv3x3，3→256 | 7,168 |
| Encoder 合计 | 450,307 |
| Query Linear，256→256，无 bias | 65,536 |
| 相对关闭旧模块的 baseline 新增合计 | 515,843 |

相同维度下，旧 V6B 两个卷积约 1,769,984 参数，旧 V7 Linear 65,792 参数。完整 V8 关闭它们，故相对现有 V7 的局部参数差约为 -1,319,933，但不能把相对 V7 的减少说成相对官方 baseline 减少。

参数少不等于空间卷积便宜。只估算新三个分支及融合卷积的 MAC：

$$H_mW_m\,[3(9D\cdot64+64)+27D].$$

当 Hm=Wm=256 时约 29.46G MAC/图，不含归一化、激活、目标生成或原模型计算。Q=700、K=350 时 Query projection 约 0.023G MAC，空间分支可能明显更贵。

这些是公式估算，不是测得的 FLOPs、GPU 延迟或 FPS。常见 1 MAC=2 FLOPs 约定也需明确。后续可评估 depthwise separable/head 降采样等替代，但本补丁没有这些优化。

## 26. 目标生成、显存和同步开销

`masks.detach().bool().cpu().numpy()` 将 batch 当前图片的全部实例 mask 复制到 CPU。若 N=700、H=W=1024，单布尔数组约 700MiB，另有原 GPU masks 和 EDT 临时数组。

每实例 CPU EDT 通常是 O(HW) 量级，整个图片约 O(NHW)；后续还为每个实例进行设备传输和 resize。Gaussian 当前也在每实例对全 feature grid 计算。

这是优先保证语义清晰的实现建议，不是为密集高分辨率森林优化的生产实现。不能忽略数据搬运可能导致 GPU 等待。

可选改进方向：只计算实例 bounding box 内 EDT、把几何图生成放在增强后的 mapper、采用正确的变换/缓存策略、局部高斯绘制。都必须保持与当前目标定义一致并验证，本文未替你修改。

separation 的负相似度和跨状态 GT equality 都有 O(Nmatch²) 矩阵；使用 `.item()` 统计 pairs 也会产生设备同步。当前 matcher 本就需要 CPU Hungarian，但新增同步仍需测量。

## 27. 当前需要正视的限制

1. Center heatmap 的低分辨率中心碰撞无法由单通道图区分。
2. 固定 sigma、固定 NMS 窗口可能压制密集小树；平坦峰值又可能保留多候选。
3. 裁剪树冠的 EDT 中心不一定是真实树干位置；凹形/多峰形状更复杂。
4. Dense geometry map 无实例 ID，不能独立恢复完整实例归属。
5. Query sampling 不向 query_embed 注入实际中心坐标；不是坐标锚定 Decoder。
6. Top-K ranking 不可导，漏选位置不会从这条路径获得坐标优化。
7. 训练早期预测质心成本可能不可靠；没有 warm-up。
8. separation 正项可能过度约束跨层表征，负项仅覆盖 matched 邻近 GT。
9. padding 不是在整网内完全屏蔽，GN/卷积/原 point loss 仍有影响。
10. EDT 生成和空间卷积开销尚未实测，密集图可能显著慢。
11. 本地 rank 的新 loss 平均不等于全局像素/pair 严格加权平均。
12. baseline 模式仍用旧 criterion，不能继承全部 V8 空匹配防护。
13. 四阶段配置不等于充分的单因素消融。
14. 数值极值、DDP、AMP、checkpoint 迁移均未运行验证。

标注质量也很重要：若图像中漏标树木，Center 负样本监督会把这些真实树冠当背景。本补丁没有处理 incomplete annotation 或 overlapping instance 的特殊约束。

## 28. 推荐的严谨消融安排

保持同一 Backbone、数据划分、增强、输入分辨率、Q、batch size、优化器、训练步数和推理策略。

开发阶段 A/B/C 可保留，但论文归因建议额外做：

| 实验 | 只改变什么 | 目的 |
|---|---|---|
| Base | 无 V6B/V7/V8 | 基础对照 |
| Center-only structure | 仅中心编码/监督 + Hybrid Query | 排除未监督分支的混入；需要额外结构开关 |
| +Boundary supervision | 单独加入 dense boundary loss | 判断边界监督收益 |
| +Distance supervision | 单独加入 distance loss | 判断距离监督收益 |
| +Mask feature fusion | 仅改变 MASK_FEATURE_FUSION | 区分 Query 路径与 Mask 路径 |
| +Mask Boundary Dice | 单独启用 MASK_BOUNDARY_WEIGHT | 区分两种 Boundary loss |
| +Geometry match | 单独启用 matcher cost | 衡量分配改变 |
| +Separation positive | negative_weight=0 | 跨状态一致性是否有益 |
| +Separation negative | positive_weight=0 | 邻近实例排斥是否有益 |
| Full | 综合选定项 | 最终方案 |

至少报告实例 AP/AP50/AP75、小树冠指标、密集区域指标、边界质量及运行成本。若声称减少粘连，应有针对性案例或指标，不能只看总体分类正确率。

重复种子和等预算实验有助于判断变化是否超过训练波动。本文没有任何性能数据，因此不能从代码直接得到创新有效性的结论。

## 30. 实现与最初结构图的对照

| 图/设计概念 | 补丁实际实现 | 应怎样描述 |
|---|---|---|
| 三种树几何先验 | 三个 logits 分支 + 逐实例 GT 监督 | supervised geometry responses |
| Geometry Feature | sigmoid maps 拼接、3x3 卷积、残差融合 | 不只是三张图相加 |
| Tree-aware Query | 峰值采样特征、投影、置信残差 | 原 Q 个槽中的部分内容增强 |
| 中心引导定位 | discrete local peaks / Top-K | 不属于可微坐标预测 |
| 相同实例吸引 | 相邻预测 states 的同 GT matched Queries | 跨状态一致性，含初始 state |
| 不同实例排斥 | final matched 邻近实例的 cosine hinge | 不是所有 Query 的通用去重 |
| Geometry matcher | mask soft centroid 与 GT centroid 的 L1 | 不与 EDT 中心或 Top-K 点绑定 |
| Radial distance | normalized internal EDT | 是到边界距离，不是到中心距离 |
| 完全从官方 baseline | 本分支中关闭已识别旧模块 | 尚未完成官方 release 全仓库对齐 |

这份说明给出的是当前补丁可明确追踪的行为与理由。论文术语应围绕这些实际机制组织，并通过独立实验支持，不应把示意图里未实现的机制写成既有结果。
